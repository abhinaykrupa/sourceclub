- Stripe Customer = parent bill-to entity.

- Billing status
- Active subscription count
- MRR / ARR
- Failed payment flag
- Last invoice paid date
- Dunning / past due status
- Subscription-by-location rollup.

**Implementation**
1. Build a canonical mapping table between Stripe customer, Stripe subscription, HubSpot company, HubSpot location.
2. Run one-time backfill + fuzzy/manual reconciliation for current records.
3. Add Stripe webhooks for `customer.updated`, `subscription.*`, `invoice.*`, `payment_intent.*`.
4. Push normalized billing snapshot to HubSpot custom properties nightly plus near-real-time webhook updates.
5. Exception queue for unmapped or ambiguous entities.

- It fits their multi-location billing reality better than native tools.
- It creates the data spine needed for later dashboards and health scoring.
